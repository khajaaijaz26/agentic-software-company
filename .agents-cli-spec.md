# Agent Company CLI — Approved Implementation Spec

## Overview

Implement the v0.2 terminal-platform blueprint supplied in
`Agent-Company-CLI-Terminal-Platform-Blueprint-v0.2.docx` as a strict
TypeScript/Node.js vNext inside this repository. Preserve the existing Python
core and MCP server as a compatibility surface, but harden their approval,
contract, packaging, and audit behavior.

The vNext product is a local-first control plane: a CLI/TUI submits typed
commands to one authoritative controller, the controller persists append-only
events and projections in SQLite, and deterministic services govern task
scheduling, budgets, tools, approvals, attachments, artifacts, and connected
platform actions. Model and connector output is untrusted data, never authority.

## Architecture and Delivery Shape

- Strict TypeScript npm package with the `agent-company` executable.
- Componentized CLI/TUI, controller, worker, and package modules in the existing
  `apps/`, `packages/`, and `adapters/` topology.
- Local SQLite/WAL event store with command idempotency and rebuildable
  projections; no remote control-plane listener in v1.
- Deterministic fake worker and provider-neutral adapter interfaces for an
  end-to-end local vertical slice without requiring paid credentials.
- Lazy activation from the canonical 25-role prompt catalog.
- Exact, actor/action/resource/environment/artifact-bound, expiring,
  single-use approvals.
- Content-addressed artifacts and local-first attachment receipts with scans,
  lineage, quarantine, explicit projection, and no implicit transfer.
- Normalized connector actions for GitHub, Vercel, and Supabase. Read-only
  discovery may run after connection validation; every mutation is planned,
  risk-classified, separately approved where required, idempotent, audited, and
  reconciled after uncertain outcomes.
- Code-native SVG/PNG branding because the blueprint contains no embedded logo.

## Example Use Cases

1. `agent-company init` previews and creates `.agent-company/project.toml` and
   `.agent-company/policy.toml` without storing secrets.
2. `agent-company run "Fix the authentication bug"` creates a durable run,
   assigns the smallest sufficient roster, renders truthful task/agent state,
   and completes a deterministic vertical slice with evidence.
3. `agent-company attachments add requirements.docx` snapshots and scans local
   bytes, emits a receipt, and performs no provider or remote transfer.
4. `agent-company integrations test github` verifies the authenticated GitHub
   CLI and reports scoped account metadata without mutating a repository.
5. `agent-company repo push --plan` produces a normalized, hashed action;
   execution requires the exact applicable approval and cannot imply PR creation.
6. `agent-company approvals approve <id>` binds a human decision once; replay,
   expiry, target drift, or actor drift fails closed.
7. `agent-company pause`, `resume`, `cancel`, and `state check` reconstruct and
   report authoritative state after restart.

## Tools and External Integrations

- Node.js built-in SQLite for local authoritative state.
- Git and GitHub CLI for source-control discovery and governed operations.
- Vercel and Supabase CLIs behind connector adapter interfaces.
- Provider/model adapters behind capability discovery and secret-reference
  interfaces; no credential is included in model context or project files.
- Optional OS credential backend; environment/keychain references are opaque.
- Existing Python MCP server remains available as a compatibility adapter.

## Constraints and Safety Rules

- No model, agent, plugin, repository text, attachment, terminal output, or
  connector response can approve an action or directly mutate controller state.
- No implicit upload: selecting a file permits only bounded local ingest.
- No secret values in project files, command output, events, telemetry, audit
  bundles, snapshots, or Git history.
- Mutations require canonical path/target checks, policy evaluation, stable
  operation hashes, idempotency keys, and evidence.
- Git push and pull-request creation are separate operations. Preview and
  production deployment are separate. Supabase production reset/seed and
  production secret copying are hard denied.
- Unknown operations, stale approvals, ambiguous targets, changed candidates,
  unsupported connector versions, and uncertain external outcomes fail closed.
- Existing unrelated code/configuration remains intact; Python compatibility is
  tested alongside the TypeScript vNext.
- No deployment or package publication is part of this implementation. GitHub
  push of the completed repository change is explicitly authorized by the user.

## Success Criteria

- TypeScript strict typecheck, lint, build, and deterministic test suites pass.
- Existing Python tests pass with MCP tests actually executing.
- At least 25 canonical roles are discoverable and dormant roles make no calls.
- Event append, idempotent command replay, DAG cycle rejection, budget race,
  approval binding/expiry/replay, artifact integrity, attachment scan/no-transfer,
  connector risk classification, terminal sanitization, and crash replay have
  automated coverage.
- CLI supports JSON/plain/non-interactive output and stable documented exit codes.
- TUI renders dashboard, agent cards, tasks, events, approvals, cost, and narrow
  terminal fallbacks from authoritative state.
- `npm pack --dry-run` contains the executable and required runtime assets.
- Python wheel contains prompts, schemas, and workflows and resolves them after
  non-editable installation.
- No tracked secret or generated runtime database is present.
- README, installation, architecture, threat model, command reference,
  compatibility matrix, and blueprint traceability match the implemented surface.

## Reference Samples

## Assumptions

- The supplied blueprint is the user-approved product specification and review
  gate for this non-interactive build request.
- The npm scope/package name remains a project-owned placeholder until the owner
  reserves it; the executable name is stable as `agent-company`.
- v1 is local single-user/single-controller. Hosted multi-tenant control planes
  remain explicitly post-1.0 as required by the blueprint.
- Live paid model calls, production deployments, production database mutations,
  and package publication are not needed to prove this repository upgrade.
